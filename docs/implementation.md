# 현재 구현 범위와 출시까지 남은 작업

## 구현한 범위

- 직원 앱·관리자 웹·공통 UI/도메인/API 계약의 React·TypeScript·Tailwind 모노레포.
- 서버 로그인·일회용 직원 초대/재발급·비밀번호 재설정·퇴사자 세션 차단.
- 서버 시각 출퇴근·재전송 중복 방지·출근/퇴근 정정·원본과 승인 이력 보존.
- 사무실 GPS 설정·거리/오차/신선도 판정·승인 외근 예외. 실제 중심 좌표는 현장 확인 대기.
- 연차 1일 480분·반차 240분, 관리자 기초 잔액·조정, 승인 차감과 취소 승인 복원, 변경 불가 원장.
- 다일 연차의 실제 사용일수 입력·관리자 차감 확인. 근무 요일/공휴일을 임의 추정하지 않음.
- 전사 월별 실제 기록 집계·감사 이력을 남기는 CSV 추출·마감·사유 있는 재개방·버전별 마감본 보존.
- 관리자 TOTP 2단계 인증·암호화한 비밀키·재사용 방지·일회용 복구 코드.
- iOS Keychain·Android Keystore bearer 저장·HTTPS 네이티브 통신·사용 중 GPS·CSV 공유 연결.
- Docker/HTTPS/영속 볼륨 배포 구성, online backup·무결성 검사·별도 복구 검증.
- 웹·서버·도메인·통신 테스트와 Android/iOS 컴파일 CI.

## 실제 외부 설정·기기가 필요한 남은 단계

1. Oracle Always Free + DuckDNS의 1인 베타 HTTPS 배포. 계정 가입부터 필요하며 서버·주소·운영 계정은 아직 생성하지 않음. DuckDNS 자동 갱신 구성과 [단계별 안내](oracle-beta.md)를 준비함.
2. 실제 사무동 7층에서 사무실 중심 좌표·반경을 확인하고 Android/iPhone GPS 실패율 측정 후 활성화.
3. 회사 Apple/Google 개발자 계정·식별자·서명 키와 테스트 배포 설정, 실제 휴대폰 설치·QA.
4. 회사 계정·잔여 연차 이관과 대체 관리자 지정, MFA 키/복구 코드의 회사 보관.
5. 실제 서버 외부 백업 보관·장애 알림 수신처 구성, 실제 볼륨 복구·롤백 훈련.
6. 푸시를 도입할 경우 회사 Firebase/APNs 자격정보와 알림 정책 선택. 현재 푸시 발송을 구현·수행했다고 표시하지 않음.
7. 기록·좌표 판정 근거·첨부·감사·백업 각각의 보관/파기 정책 확정. 임의 자동 삭제는 실행하지 않음.
8. 소수 직원 파일럿과 기존 기록 병행 후 한 번의 실제 월별 마감 검증.

## 회사 규칙 중 아직 필요한 결정

출근 마감·코어타임·근무 요일/공휴일, 08:00 이전 근무 인정, 반차가 배치되는 정확한 시간 구간, 점심 중 업무·개인 외출·외근 시간 구간·자정 넘는 근무 기준. 연차 자동 발생/소멸/촉진과 급여 금액은 현재 자동화하지 않습니다. 반차는 잔액에서 4시간 차감하지만 하루 실근무 목표에 자동 반영하지 않으므로 근태/휴가 시간을 합친 급여 인정 집계로 사용하면 안 됩니다.

현재 월별 보고서는 실제 출퇴근과 점심 중첩 제외를 집계합니다. 예정 근무 대비 결근·급여·미확정 휴가 인정시간을 추정하지 않습니다. 마감된 월의 정정/휴가 변경은 재개방이 필요하고, 누락·확인 필요·대기 신청/휴가 취소가 있으면 마감하지 않습니다.

## 검증 원칙

단순 화면 시연과 실제 API 테스트를 분리합니다. 실제 테스트는 임시 DB와 별도 계정을 사용하고, 회사 사용자·비밀값·DB를 저장소에 포함하지 않습니다. 브라우저 테스트와 네이티브 컴파일, 실제 현장·휴대폰 검증은 서로 다른 완료 기준입니다.
