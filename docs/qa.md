# 사내 파일럿 QA 실행표

## 테스트 준비

운영 자료와 분리한 환경에 관리자 A·B, 직원 C·D를 준비합니다. 관리자는 서로의 신청을 승인하고 본인 신청은 다른 관리자가 처리합니다. 테스트 비밀번호·초대 코드·복구 코드·위치 원문은 이 문서나 GitHub 이슈에 기록하지 않습니다. 각 결과는 실행일·앱 버전·OS·기기·기대 결과·실제 결과·재현 순서로 남깁니다.

## 기능별 통과 기준

| 영역      | 실행 순서                                                                  | 통과 기준                                                                         |
| --------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 초대      | 초대 → 활성화 → 같은 코드 재사용 → 재발급                                  | 한 번만 활성화되고 폐기된 코드는 거절됨                                           |
| 인증      | 잘못된 비밀번호, 로그아웃, 만료, 관리자 비밀번호 재설정, 직원 비활성화     | 올바른 오류가 표시되고 이전 세션/비밀번호의 접근이 차단됨                         |
| MFA       | 등록 → 새 로그인 → 같은 OTP 재사용 → 복구 코드 재사용                      | 정상 OTP/복구 코드는 통과하고 재사용은 차단됨; MFA 미등록 관리자는 운영 작업 불가 |
| 출퇴근    | 출근 → 연속 탭/네트워크 재전송 → 퇴근 → 새로고침                           | 서버 시각으로 기록되고 중복 기록 없이 화면과 DB 결과가 일치함                     |
| 점심      | 11:00–14:00, 12:00–14:00, 13:00–18:00 기록을 도메인 테스트에서 검증        | 실근무가 각각 90분, 60분, 300분으로 계산됨                                        |
| 정정      | 직원 신청 → 다른 관리자 승인 → 원본/이력 조회                              | 승인 시각과 원본이 별도로 보존되고 두 관리자의 동시 처리로 중복 승인되지 않음     |
| 연차      | 기초 잔액 16시간 → 연차 승인 → 반차 승인 → 해당 연차 취소 승인             | 잔액이 16 → 8 → 4 → 12시간; 중복 승인/취소로 추가 차감·복원되지 않음              |
| 휴가 오류 | 잔액 초과, 날짜 중복, 다일 휴가 일수, 본인 승인                            | 잘못된 신청/승인은 차단되고 잔액·원장에 부분 변경이 남지 않음                     |
| 월별 보고 | 직원 기록 대조 → CSV → 미완료 신청이 있는 과거 월 마감 시도 → 처리 후 마감 | CSV와 실제 기록이 일치하고 누락/대기 건이 있으면 마감이 거절됨                    |
| 마감      | 마감된 월 변경 시도 → 사유로 재개방 → 변경 → 재마감                        | 마감 중 변경은 차단되고 이전 마감본·재개방 사유·새 버전이 남음                    |
| 권한      | 직원으로 관리자 API 직접 요청, 다른 직원 자료 요청                         | 화면 숨김뿐 아니라 서버에서도 접근이 차단됨                                       |
| 복구      | 실행 중 백업 → 별도 빈 환경 복원 → 로그인/근태/휴가 원장 대조              | 원본 변경 없이 무결성 검사와 데이터 대조가 통과함; 같은 MFA 보관 키 사용          |

08:00 이전 인정, 공휴일, 반차 배치, 자정 넘는 근무 등 미확정 규칙은 임의 기대값으로 출시 승인하지 않습니다. 월별 실제 근무 보고서를 급여 인정시간으로 해석하지 않습니다.

## 실제 사무실·휴대폰 검사

위치는 사무동 7층에서 iPhone과 갤럭시 각각 여러 번 측정합니다. 출입구·좌석·창가의 허용 여부, 건물 밖에서의 거절 여부와 실패 빈도를 기록하고 회사가 허용 반경을 결정합니다. GPS는 층수를 증명할 수 없으므로 7층 출입 확인 용도로 간주하지 않습니다. GPS를 켜기 전에는 현장 확인이 끝나지 않았다는 설정 상태를 유지합니다.

두 기기에서 위치 권한 허용/거부/대략적 위치, GPS 꺼짐, 네트워크 단절·복구, 앱 종료·재실행, 잠금·복귀, 서버 세션 회수, CSV 공유/취소를 확인합니다. 글자 확대, 작은 화면, 키보드, 안전 영역, Android 뒤로 가기, VoiceOver/TalkBack도 검사합니다. 네트워크 복구만으로 출퇴근 성공을 표시하지 않고 서버 저장 결과를 확인합니다.

## 현재 검증과 출시 순서

웹·API 자동 검사는 GitHub `Application checks`에서 확인합니다. Docker API는 읽기 전용 루트/비루트 계정에서 건강 상태, 관리자 생성, 네이티브 로그인·세션, 백업 무결성을 별도 임시 계정으로 실행 검증했습니다. `Native build checks`의 컴파일 결과는 실제 휴대폰 QA 결과와 별도로 기록합니다. 회사 계정·실제 GPS·서명한 설치 앱·운영 복구 훈련은 아직 실행하지 않았습니다.

1. 회사 정책·서버·도메인·운영 담당자와 대체 관리자를 확정합니다.
2. HTTPS 배포, MFA, 외부 백업, 실제 기기 설치를 준비합니다.
3. 위 표와 현장 검사를 수행하고 기록 손실·권한 오류·잔액 불일치가 있으면 수정 후 해당 흐름을 재검사합니다.
4. 소수 직원이 기존 기록과 병행합니다. 출퇴근·휴가·정정·한 번의 월 마감까지 대조합니다.
5. 운영 담당자가 이관 잔액·백업 복구·문의 대응을 확인한 뒤 전 직원으로 확대합니다.
