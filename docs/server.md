# 서버 연결과 운영 경계

## 실행과 데이터

Node 24의 `node:sqlite`를 사용하는 단일 API 인스턴스 구조입니다. 20명 사내 사용의 개발·파일럿을 대상으로 합니다. `pnpm bootstrap`으로 빈 DB에 초기 관리자 1명을 생성하며 중복 초기화는 거부합니다. `.env`는 `apps/api` 실행 디렉터리에서 로드합니다. 환경에 제공된 값이 있으면 로컬 파일보다 우선합니다.

DB에 마이그레이션 버전을 보관하고 시작 시 적용합니다. 계정·초대·세션·근무·요청·원본 이벤트·감사 이력·중복 요청 결과·근무지 설정을 저장합니다. WAL, 외래키, 사용자/근무일 유일 제약과 동기 트랜잭션을 사용합니다. 원본 이벤트와 감사 이력은 앱 DB 트리거로 수정·삭제를 막습니다. DB 관리자까지 막는 변조 방지 장치는 아닙니다.

원본 출퇴근은 UTC 시각을 저장합니다. 근무일·표시·같은 날 계산은 한국 시간대를 사용합니다. 정정 시 `corrected_start`/`corrected_end`를 별도로 적용하고 원래 `start_at`/`end_at`는 바꾸지 않습니다. 누락 퇴근 승인 시 원본 퇴근은 null 그대로이고 승인된 시각으로 근무를 종료합니다. 정정 요청 당시 기록 버전이 달라지면 승인을 거부하고 재신청하도록 합니다.

현재 `build`의 API 단계는 타입 검증입니다. 서버 실행은 `tsx src/main.ts`이며 별도 JS 산출물을 생성한다고 가정하지 않습니다. 웹 빌드는 각 앱의 `dist`입니다.

## 인증

- 비밀번호: 임의 salt를 사용한 scrypt, 최소 12자. 평문 저장·출력 없음.
- 세션: 임의 256비트 토큰의 해시를 DB에 저장, 8시간 만료.
- 브라우저 쿠키: HttpOnly, SameSite=Lax, Path=/api. 운영은 Secure.
- CSRF: 허용 Origin 검사와 세션별 토큰을 함께 검사.
- 로그인 실패: 계정·IP 단위 제한, 미존재/비활성 계정은 같은 오류.
- 권한: 매 API 요청에서 재직·관리자 여부를 서버에서 검증.
- 비활성화: 모든 기존 세션과 미사용 초대 토큰 즉시 회수. 근태 이력 유지.
- 관리자는 타인의 요청만 승인·반려할 수 있음. 본인은 대기 요청 취소 가능.
- 초대 토큰은 해시만 DB에 저장하고 72시간 뒤 만료. 재발급 시 이전 코드 무효화.

비밀번호 재설정·관리자 MFA·운영용 모니터링·보관/파기 자동화는 후속 작업입니다. 현재 버전을 인터넷에 곧바로 공개하는 운영 완료본으로 취급하지 않습니다.

## API

| 경로                                     | 역할                                   |
| ---------------------------------------- | -------------------------------------- |
| GET /api/health                          | 상태                                   |
| POST /api/auth/login                     | 이메일·비밀번호 로그인                 |
| POST /api/auth/activate                  | 초대 코드 활성화                       |
| GET /api/auth/me                         | 현재 계정·CSRF 토큰                    |
| POST /api/auth/logout                    | 세션 회수                              |
| GET /api/workspace                       | 본인 근태·허용 범위 요청·팀 현황·정책  |
| POST /api/attendance/clock               | 서버 시각 출퇴근, Idempotency-Key 필수 |
| POST /api/requests                       | 휴가·외근·정정 신청                    |
| PATCH /api/requests/:id                  | 승인·사유 있는 반려·본인 취소          |
| POST /api/admin/invitations              | 직원·관리자 초대                       |
| POST /api/admin/employees/:id/invitation | 미사용 초대 재발급                     |
| POST /api/admin/employees/:id/deactivate | 계정 차단                              |
| PATCH /api/admin/office                  | 근무지 GPS 설정                        |
| GET /api/admin/audit                     | 최근 감사 이력 200건                   |

401은 재로그인, 403은 권한·Origin·CSRF·위치 범위, 409는 중복·동시 변경·기존 상태 충돌입니다. 검증 실패는 400입니다. 출퇴근은 같은 키의 재시도에 기존 결과를 반환하며, 같은 키의 다른 동작은 거부합니다. 클라이언트가 보내는 임의 근무 시각은 허용하지 않습니다.

## 배포 준비

개발 프록시와 운영 리버스 프록시는 별개입니다. 운영에서는 HTTPS 웹 도메인의 `/api`를 비공개 API로 전달하고 `APP_ORIGINS`에 정확한 직원·관리자 Origin만 넣습니다. 운영은 `NODE_ENV=production`이며 허용 Origin 설정이 없으면 시작을 거부합니다. 세션을 localStorage에 저장하지 않습니다. 브라우저 쿠키를 사용하는 현재 구현을 네이티브 Keychain·Keystore 저장 구현으로 간주하지 않습니다.

DB는 영속 로컬 볼륨에 두고 단일 API 인스턴스로 운영해야 합니다. 서버리스의 임시 파일시스템이나 여러 인스턴스가 각자 가진 DB에 두면 안 됩니다. 다중 인스턴스가 필요하면 PostgreSQL 등의 저장소로 변경합니다.

백업은 SQLite online backup 또는 정상 종료 후 DB와 WAL 상태를 고려한 절차로 구성해야 합니다. 실행 중인 DB 파일 하나만 임의 복사하지 마세요. 출시 전 실제 백업 복구 훈련과 계정·근태 자료별 보관기간·파기 정책을 확정해야 합니다. 이 단계에서 운영 백업 자동화나 배포는 수행하지 않았습니다.
